### 需要优先改善的体验

| 观察 | 对体验的影响 | 下一步方向 |
| --- | --- | --- |
| 主体还是一块木桌上的灰色棋盘，周围大面积空背景 | 看不出这是哪一个地方，也缺少进入游戏世界的感觉 | 建立一处有来历的棋庭与外围环境 |
| 固定障碍主要由逐格石柱组成，边界墙朝中心转向，形成斜向拼接 | 视觉密集，墙体像资产堆放，轮廓和空间组织不够清楚 | 连续低墙、少量立柱、明确边界，重新控制比例与朝向 |
| 阵营主要由四色棋子和出生格表示 | 红蓝绿黄有区别，但没有身份、所属组织和争夺动机 | 四个同规则阵营，各有徽记、旗帜和简短背景 |
| 传送门已经发光，但配对关系主要靠颜色 | 暖色门的区别有限，玩家需要记忆；光效强度与重要性没有统一层级 | 配对符号、入口/出口反馈、低强度常驻光与短促事件光 |
| 终点是绿色圆片，机关预告是方形薄板，道具与石柱是另一套表达 | 可行动、危险、机关、装饰的视觉语言不统一 | 共用符文线条与形状体系，并保留可辨识的功能差异 |
| 已有移动、缩放、震动、爆炸和烟花等钩子 | 不是“没有特效”，而是缺少统一的主题、时序和强弱标准 | 按事件设计表现表，逐项校准到同一套魔法机关主题 |
| 开局以主题、颜色、操作说明为主 | 玩家知道怎么点击，却不清楚“我是谁、为什么在这里、赢了意味着什么” | 轻量开局叙事、场内环境线索与对应胜利结局 |

以上场景判断基于当前截图和代码。音效实际听感、全局性能、长局策略性和多人联机稳定性尚未实测，不能据此判定已经通过或存在确定故障。

## 2. 推荐创意方向：失序遗迹中的“机关棋庭”

**提案设定，等待后续审阅定稿：**古代遗迹的“界钥”苏醒，四支探索队进入机关棋庭。每队以十枚符文傀儡投射自己的力量。傀儡沿遗迹的导能轨道滑行，门阵连接远处，机关墙在每个回合结算时升降。率先令五枚傀儡连成共鸣线，或成为最后仍保有力量的一方，就获得界钥。

这个方向与当前地牢资产、滑行规则、墙体和传送门相容。第一版以一张完整棋盘的体验为目标。剧情通过短文、徽记、摆设、声音和事件演出呈现。

### 故事与规则对应

| 现有规则元素 | 故事解释 | 场景或反馈载体 |
| --- | --- | --- |
| 棋子与手中储备 | 符文傀儡与剩余投射力量 | 统一棋子主体、阵营底座、储备刻度 |
| 骰子决定 1–6 次滑行 | 机关骰释放本回合的能量脉冲 | 骰子刻印、点数闪光、HUD 能量格 |
| 出生点与专属门 | 阵营锚点与只能识别己方印记的封印门 | 角落徽记、旗帜、门框或低矮光栅 |
| 固定墙与升降墙 | 遗迹结构与周期机关 | 低石墙、机关槽、金属边、升降符文 |
| 四对传送门 | 同印记门阵相互连接 | 每对独立符号、地面纹样、配对预览 |
| 围杀和棋子消耗 | 傀儡的能量通道被封锁，投射被解除 | 围杀预告、封印收束、储备计数变化 |
| 五连胜利 | 五枚傀儡形成共鸣线，夺得界钥 | 逐枚点亮、连线、界钥投影、结局短句 |
| 最后存活者胜利 | 其余探索队失去投射力量 | 存活阵营印记占据棋庭、单独的胜利文案 |

“能量通道”只用于解释规则，不引入额外能量数值。围杀条件、结算顺序、自吃限制、墙体压制与传送停点必须按现有规则确认，不能把故事表述写成“所有零气棋子立即死亡”。

### 四个阵营的第一版提案

| 颜色 | 暂定身份 | 可视标记 | 动机 |
| --- | --- | --- | --- |
| 红 | 赤炉探勘团 | 炉火/锤形徽记、红旗、铜饰 | 将界钥用于重启地下炉城 |
| 蓝 | 苍印档案会 | 印章/波纹徽记、蓝旗、银饰 | 封存遗迹知识，阻止失控 |
| 绿 | 苔庭守望者 | 枝叶/菱形徽记、绿旗、石饰 | 让遗迹停止侵蚀地表 |

四方保持相同玩法与棋子能力。第一版优先用底座、徽记和旗帜建立身份；只有现有棋子仍不够辨识时，再考虑新的角色模型。

### 叙事交付量

- 一份一页世界观：地点、冲突、四方动机、界钥的意义。
- 一段约 80–120 字的可跳过开局文案，进入对局后可再次查阅。
- 四张阵营卡，每张两句背景，加颜色和徽记。
- 四张道具说明卡：保留规则名称，补主题名称与准确效果。
- 五连与最后存活两种胜利文案，说明实际获胜原因。
- 三处环境线索，例如破损碑铭、未完成的调查记录、四方残旗；放在棋盘外围。

## 3. 场景构成方案

推荐先完成**遗迹大厅中的机关棋庭**，将当前木桌原型转为有明确结构的石质机关台。保留桌游式稳定全盘视角，外围环境负责建立地点感。

| 场景层级 | 具体内容 | 制作要求 |
| --- | --- | --- |
| 棋盘功能层 | 19×19 格、路径、墙、阵营门、机关槽、传送门 | 规则位置和通行性清楚，装饰不能让可走格看起来被堵 |
| 阵营层 | 四角锚点、旗帜、徽记、少量不同摆设 | 视觉权重和尺寸对称，颜色与符号双重辨识 |
| 场所层 | 石台边框、断阶、残柱、碑刻、火盆、外圈地面 | 构成前景/主体/背景，保持棋盘为最醒目的区域 |
| 氛围层 | 暖火光、弱冷色遗迹光、少量尘埃与环境声 | 低频、低亮度，不能遮盖路径和危险提示 |

具体做法：

1. 将连续固定墙做成连续低墙或石质挡块，用立柱标注转折和重点，减少逐格同一柱体的重复感。
2. 边界墙按棋盘边缘方向拼接，统一模型朝向、缩放和间距，避免整圈墙片向中心倾斜排列。
3. 固定墙、阵营门、升降墙使用不同轮廓和边缘纹样，禁止只依靠材质亮暗区分。
4. 四对传送门采用四个配对符号，悬停或选路时高亮对应出口。门户颜色与阵营身份分开表达。
5. 机关槽的平放态、预告态、升起态使用同一套机关底座，避免“预告方片”和“实际石柱”像两类对象。
6. 棋子维持紧凑轮廓，增加稳定编号/徽记或底座标识；不为场景表现引入职业技能。
7. 先确定基础光照和材质，再补 Bloom、雾和粒子；常驻传送光降低至不压过选中、危险和胜利反馈。
8. 根据 HUD 实际占用区域调整棋盘构图。保留全盘与俯视两种视角；环境高物体不遮住四角棋子。

先交付一张全盘和一张局部截图供审阅，再铺设完整外围环境。每次增加装饰后，从实际游戏镜头检查通路、棋子和门户的可见性。

## 4. 特效与声音：按事件建立共同语言

现有 `MatchEvent`、DOTween 动画、Cinemachine、FX Prefab 和音效入口可以复用。实现时先梳理事件播放顺序，再替换具体效果，避免结算结果、移动动画与 UI 各自抢先表达。

| 事件 | 推荐视觉与声音 | 优先级 |
| --- | --- | --- |
| 悬停与选择 | 底座边线、轻微抬起、短点击声；显示同阵营徽记 | P1 |
| 合法滑行预览 | 符文轨迹、方向箭头、终点圈；跨门时显示入口与出口段 | P1 |
| 出子 | 锚点亮起，傀儡短暂凝聚，储备数字同步减少 | P1 |
| 滑行 | 简短地面轨迹、轻石摩擦声；撞到止点有小幅停顿 | P1 |
| 传送 | 入口收束→出口亮起→傀儡出现；用相同配对纹样 | P1 |
| 升降墙 | 槽位预告→机械运动→少量尘屑→状态稳定；升降音色有区别 | P1 |
| 道具拾取与使用 | 拾取飞入库存；四种道具分别表达穿墙、急停、撞吃和破墙 | P1 |
| 危险与围杀 | 危险轮廓加符号；围杀时封印收束、消耗计数变化 | P1 |
| 四连威胁 | 四枚同色棋子共鸣脉冲，弱提示线；强度低于实际胜利 | P2 |
| 回合交接 | 下一阵营锚点短脉冲、HUD 提示与短提示音 | P1 |
| 五连胜利 | 逐枚点亮→清楚的五连线→界钥投影→结算；代替泛用烟花作为主表现 | P1 |
| 最后存活胜利 | 单独的阵营印记演出和文案，避免出现不存在的五连线 | P1 |
| 环境 | 火盆、尘埃、远处低声共鸣；后续再加轻背景音乐 | P2 |

制作标准：每种效果有统一颜色、尺寸、持续时间与声音层级；小事件短促，大事件有辨识度。选中反馈、危险反馈和阵营色不能只靠相同的红/绿色区分。短效果通常控制在约 0.15–0.8 秒内，胜利演出可更长并允许跳过；这些是制作目标，不是本轮测得的数据。

音效优先试听并复用 `Assets/Resources/Sfx` 与 `Casual Game Sounds U6`。目前核查的 `DraftlineAudio` 主要是事件 `PlayOneShot`，后续另列环境声、音乐和音量设置任务。音量、短促提示的重复感和空间听感需要实际试听后决定。

## 5. 界面与故事一起落地

- 开局页先呈现地点、争夺目标和阵营身份，再提供人数/颜色选择。第一版集中展示已完成的主题。
- HUD 保留“骰子点数、剩余滑行、手中、消耗”等准确规则词，故事名作为辅助，避免玩家多学一套术语。
- 用阵营卡替代只有颜色名的身份表达；对局中提供简短目标提示与规则图例。
- 悬停道具说明清楚写出效果与持续范围，库存显示已激活状态。
- 急停在棋盘路径上显示可停点，避免主要依靠坐标按钮让玩家推算位置。
- 提供退出到开局、音量、演出简化/震动开关；避免只能等结算后才能处理一局游戏。
- 以 1920×1080、1366×768、1280×720 检查 HUD、故事卡和急停列表，滚动区不能吞掉主要操作。

## 7. 分阶段执行与完成标准

| B：完整棋盘构成 | P1 | 固定墙/阵营门/机关槽/传送门/棋子的一套视觉件，默认与俯视构图 | A | 所有功能格清楚、门可配对、四角可见；审阅全盘与局部截图通过 |

| D：关键事件表现 | P1 | 出子、滑行、传送、墙切换、四道具、围杀、两种胜利的视觉与声音 | B，使用 C 的光照基线 | 每种事件能从视觉辨识原因和结果；事件顺序与状态一致；同一事件不会重复播放 |
| E：故事入口与 UI 收束 | P1/P2 | 开局短文、阵营卡、图例、道具卡、结局、设置与适配 | A–D | 新玩家无需口头解释能完成一回合；HUD 和故事表达一致，主要操作可见 |
| F：完整体验验收 | 必需 | 2 人与 4 人完整对局记录、分辨率检查、音效试听、规则回归、Windows 构建验证 | B–E；工程基线核对 | 可从开局到胜利再开局；表现不误导规则、不锁死操作；没有新的 Console Error |

**最小可审阅里程碑：A + B。**先确定故事与画面方向，并交付一张视觉完整、规则可辨识的棋盘。确认之后再扩大到整个房间和完整特效。这样最先解决用户关心的场景构成问题，也避免在未定稿主题上反复制作特效。

局域网、第二主题、AI、更多棋盘、角色技能和长篇剧情放在首个完整体验之后另行评估。首版完成标准围绕现有 2–4 人同机桌游，不依靠新增这些系统才能成立。

| 联机完整性 | LAN 入口在 UXML 中隐藏；已有主机权威命令与快照，但没有本轮多人实测 | 单列后续联机验收，不能将存在网络代码等同于可用联机产品 |

## 9. 后续验收清单

1. **故事与场景：**玩家看完开局与阵营卡后，能描述场所、身份、目标；画面与文案表达同一套设定。
2. **棋盘读图：**默认镜头和俯视镜头能区分固定墙、阵营门、机关槽、传送门、棋子、道具和危险；四色之外还有符号信息。
3. **事件链：**逐项检查出子、普通滑行、传送、升降墙、四道具、四连、围杀、淘汰、两种胜利；视觉位置、声音和 HUD 与实际状态同步。
4. **完整对局：**进行 2 人和 4 人同机完整对局，记录不理解规则、看不清、事件过慢和错误点击的位置，验收再开局与返回入口。
5. **工程回归：**运行现有规则测试，对新增的事件取消/重开流程做针对性验证；构建 Windows 版本检查脱离 Editor 的表现。
6. **资源与性能：**检查实际选用材质、授权文件与构建体积；在目标机器观察粒子、灯光和 UI 开销后调整质量。不以本轮静态检查宣称性能达标。

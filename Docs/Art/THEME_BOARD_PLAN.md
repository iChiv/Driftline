# 多主题棋盘与场景美术计划

> 实施更新：用户于 2026-10-15 授权制作，五个主题的首版现已落地，见 [制作结果与编辑入口](THEME_IMPLEMENTATION.md)。下文保留为制作前的资产审查与原设计计划。

2026-10-15。**本文件仅规划美术，不代表已制作主题。**本轮已实现行动原因与规则引导，未导入新美术包，未修改现有模型、材质、棋盘构成、灯光或主题系统。资产清单、模型尺寸/Shader 抽样和预览均为只读审查产生的文档证据。

## 设计方向

规划 **五个完整场所**：前线要塞、符文地城、星舰机库、暮林祭坛、潮汐港口。19×19 玩法区成为各场所内部的战场、机关庭院或作业区，四周延续相同的建筑、功能与故事。棋子、墙、门、骰子位置、环境声音、光照和界面装饰统一设计。

首批优先完成 **前线要塞 → 符文地城 → 星舰机库**；暮林祭坛和潮汐港口为第二批。五个主题共享当前布局与规则，区别在场景构成和表现。新地图布局与新地形能力需要另行设计，不混入本次美术工作。

现有桌面版本保留作制作与规则比对基线；当前 `MagicTheme` 是 Implemented=false 的占位，不算已经有第二个主题。未来可以保留桌面为练习主题。

## 所有主题共享的构成规则

把场景分成四层，模型摆放有明确作用：

| 层 | 内容 | 摆放原则 |
| --- | --- | --- |
| 战场核心 | 19×19 格、固定墙、机关槽、四角门/出生位、传送对、中心障碍 | 与 BoardLayout 一一对应；地面格边界可读，固定/变化/可通行状态清楚 |
| 近景功能带 | 城墙外沿、护栏、灯、旗、供能/补给设施、骰子所在控制台 | 解释战场用途；留出四角与点按空间，阻挡轮廓不会误导到相邻可走格 |
| 中景叙事带 | 要塞建筑、地牢廊道、舰船设备、林中遗迹、码头商屋 | 每个主题 2–3 个主地标与若干附属模型，形成连贯功能关系 |
| 远景边界 | 城墙轮廓、洞穴、星空外舷、树林、海面 | 稳定整体空间和主题色，低频运动，不抢棋盘动作 |

默认高俯角与纯俯视都必须读清全部四角。场内矮墙目标高度约 0.35–0.65 格，棋子展示高度约 0.65–0.95 格；这些是制作起点，按镜头与模型比例实测。高建筑、树冠、桅杆和吊臂放在后方/侧后方。前景使用低矮断墙、绳索、石块等框景。

原版高墙不整体压扁成失真的模型：选择半墙、切分模块或制作低墙 Prefab 变体。保留模型轮廓、UV 和配件比例；场内占格底座清楚表达规则阻挡范围。

## 主题一：前线要塞

**场所与气氛：**四支队伍在废弃要塞的演习战场争夺核心节点。主棋盘是石质/混凝土作战庭院，外围有指挥、补给、掩体和车辆。整体为灰米色地面、低饱和军绿、暖色警示光。

| 部分 | 模型/做法 |
| --- | --- |
| 地面 | U 的地面/建筑模块与 P/Terrain 底层；压低裂纹与弹坑对比，用石缝/作业线表达格界 |
| 固定墙 | `U/WW2_T/Sandbags_Straight`、Sandbag、低障碍组合；较厚转角用混凝土低墙变体，地堡留在外围 |
| 机关槽/中心墙 | 地面升降装甲挡板与中央掩体，制作可编辑的模块变体；升起、降下、被占据状态分别有轮廓和警示纹 |
| 四角门与出生位 | `U/Military_T/Military_Gate` 的矮门/岗亭变体，四方独立军旗、底座和出发区；未参战门明确关闭 |
| 传送对 | 军用信标/投射装置，保留四对形状与配对灯；造型强调它是传送设备，不像普通路面 |
| 棋子 | `U/People_T/Man_Soldier` 及后续核查的 Rig 变体；统一角色轮廓，阵营色集中在底座、肩章/旗标 |

**周边摆放：**后侧指挥所 `Military_Headquarters` + Barracks；左侧补给区 Military_Tent + Ammo_Crate_Pak + Military_Truck；右侧 Bunker_Medium + 少量障碍/车辆；前侧低沙袋与断墙。四角都使用同一军事语言，避免把任意武器放在格内造成额外能力暗示。骰子放在侧后方指挥台；环境声用低频风声/远处设施声。

**重点与缺件：**现有建筑与掩体足够；需要制作一套低装甲机关、信标和阵营标记。先解决 U 的 URP 材质，保留纹理与多材质，不将人物和设施全部涂成单色。

## 主题二：符文地城

**场所与气氛：**地下遗迹的封印庭院，四角探索队营地争夺界钥。棋盘是一片建在完整大厅里的机关石地，外围是廊道、拱门、祭坛与补给区。冷灰石、青蓝符文、暖火把组成明暗层次。

| 部分 | 模型/做法 |
| --- | --- |
| 地面 | `K/floor_tile_small`、broken/decorated 变体、floor_foundation 边缘；装饰只在非走位格或外围出现 |
| 固定墙 | K/wall_half、wall_half_endcap、wall_corner_small 的矮墙变体；P/Dungeon 仅在适配后补外围复杂拱门 |
| 机关槽/中心墙 | K 地板格栅与低石机关块；中心用小封印台作为不可走障碍，符文强调周期变化 |
| 四角门与出生位 | K 门、柱基、四色旗；营地保持同套箱桶、武器架、火把语言 |
| 传送对 | 小符文拱门/圈阵，配对形状置于地面与门框，门框高度不挡棋子 |
| 棋子 | 同一套冒险者/傀儡兵棋与阵营底座，可从 U/People_T 的 Knight/Skeleton 候选核查；外观不带新职业规则 |

**周边摆放：**后侧封印祭坛与完整主拱门；左右廊道、破柱、火把与少量雕像；四角是小探索营地；前侧残阶、断墙、少量碎石。骰子位于侧边符文祭台。采用缓慢符文呼吸与轻环境雾，玩法区保持清晰。

**重点与缺件：**K 已有 URP 样本和完整模块，生产阻力较小。修正大厅的模型尺度与低墙端盖；不能把完整高柱平均塞入每个墙格。

## 主题三：星舰机库

**场所与气氛：**停泊舰船的货运/训练甲板，争夺中央导航核心。主棋盘是地板面板与轨道交错的作业区，外围有设备、货物、舱门和宇宙外舷。银灰、蓝灰和琥珀警示灯，少量冷光。

| 部分 | 模型/做法 |
| --- | --- |
| 地面 | U/Scifi_T/Scifi_Floor 系列与 P/SciFi modular tile；面板接缝表达格界，保持可走区亮度均衡 |
| 固定墙 | SciFi wall 的低墙/隔断变体，侧面端盖和底座统一；原整墙用于外围舱室 |
| 机关槽/中心墙 | 弹起式防护挡板、机械升降柱；固定中心障碍表现为核心基座，供能表现不改变规则 |
| 四角门与出生位 | `U/Scifi_T/Scifi_Door_Metal` 与 P/SciFi 门框的矮门变体，四色权限灯、部署台 |
| 传送对 | 相位传输盘与半高发射环；保留四对形状，进入/出口同时点亮 |
| 棋子 | U/People_T/Man_Astronaut 或统一机械投射兵棋；护甲保持材质细节，底座与头顶徽记表达阵营 |

**周边摆放：**后侧观察窗/舱门与小比例飞行器或外舷；左侧维修区、console、crane；右侧 Scifi_Cargo_Big、箱体、输送设备；前側低护栏和地面管线。骰子整合在导航控制台。环境为设施低鸣，传送声音与地城有所区别。

**重点与缺件：**P/SciFi 与 U/Scifi 都很完整，但模块原始宽度 2/4、墙高约 3，需要选定一个主资产族并统一尺度。不要直接混拼两套墙体而产生门高、格宽和材质不一致。先做可读的矮隔断、发光权限灯与传输盘。

## 主题四：暮林祭坛

**场所与气氛：**森林侵入的古代机关广场，中央树根封印仍在运转。地面是被苔藓分割的旧石台，外围是符石、倒树、林间营地和小径。低饱和苔绿、暖灰石、少量琥珀日光。

| 部分 | 模型/做法 |
| --- | --- |
| 地面 | P/Ancient Ruins、RPG Tiles 与石台变体；苔藓贴花留在边缘，不盖住格线 |
| 固定墙 | 低石垣和根系栏障，完整神庙柱/树冠放外围 |
| 机关槽/中心墙 | 升降符石与中央石根封印，四对槽位保留同样的变化节奏 |
| 四角门与出生位 | 德鲁伊石门、木图腾和林间小营地，形状与阵营色稳定 |
| 传送对 | 低符石门/菌光环，地面刻配对符号；不能与普通装饰符石混淆 |
| 棋子 | 统一探索者或木石傀儡兵棋；绿色阵营使用高饱和底座，与低饱和树林分离 |

**周边摆放：**后侧 `P/Druid Home/Rock_Prop_Tribal_Stone_Altar_Rune_01_Atlased` 及相关祭坛、残拱；左右 U/Nature_T 的 Tree_Beech、岩石、倒木和 P/Vegetation；前侧小蕨类、石阶与碎柱；四角延续营地而非随机森林。骰子位于侧边石桌。雾、飞虫和叶片保持低频、避开玩法平面。

**重点与缺件：**原祭坛高约 2.09、树高约 6.08，需要外围分层与镜头检查；树冠投影不能隐藏走位格。根系机关与傀儡形象可用已有几何制作变体。

## 主题五：潮汐港口

**场所与气氛：**环水码头的货运争夺区，四方在港口栈桥与石质集散场之间滑行。中心作业场周围是吊装设施、仓屋、帆船与栈桥。暖木、浅灰石、低饱和海蓝，灯火点缀。

| 部分 | 模型/做法 |
| --- | --- |
| 地面 | 石质码头为玩法核心，木板用于外围栈桥和部分可读边框；缝线对应格界 |
| 固定墙 | 低货箱挡墙、石护栏与木障碍；箱体用占格底座区分可拾取道具 |
| 机关槽/中心墙 | 升降防水闸/货运挡板，中央不可走调度基座；首版不加入潮汐新规则 |
| 四角门与出生位 | 四个泊位出发区、小旗、绳桩、门架；相同阵营权限语义 |
| 传送对 | 灯塔信标/货运投射台，地面配对图形明确 |
| 棋子 | U/People_T/Man_Pirate、Man_Pirate_Captain 等候选兵棋，统一轮廓与阵营底座 |

**周边摆放：**后侧 `U/Pirates_T/Ship_Colonial` 或 Ship_Pirate 泊船；左侧 Dock_Wood + Crane_Wood + 吊装箱；右侧 House_Pirate_Medium、Shack 与堆货；前侧短栈桥、系缆桩、绳索与低护栏。海面包围外围，主棋盘是一块明确完整的可走陆地。骰子位于码头调度桌。

**重点与缺件：**帆船与桅杆显著高于棋盘，船应在侧后方水面；水材质需单独适配 URP，项目的 Stylized Water BIR 不能默认当作现成 URP 水方案。需要低闸门与传送信标变体。该主题材质/水面和轮廓工作最多，放最后。

## 场景组织与未来主题系统

现有 BoardTheme 主要换材质与激活 Tabletop/Magic 层，不足以承载完整模型、灯光、音频和棋子主题。后续建议在同一玩法场景中组织为：

```text
GameplayRoot（规则、会话、网络、统一点按）
BoardBindings（每格语义、碰撞代理、机关动画绑定）
ThemeContainer
  FrontierFortress / RuneDungeon / StarshipHangar / ForestShrine / TidalHarbor
    BoardSurface / FixedWalls / MovingWalls / Gates / Portals
    FactionBases / NearSet / Landmarks / Background
    Lighting / AmbientAudio / DicePresentation
UIRoot（正式 Prefab；主题调整色板/图标，布局保持可手改）
```

主题以保存的 Prefab、Prefab Variant、Material 和配置资源制作。编辑器一次绑定后，可直接在场景或 Prefab Mode 调整；不在 Play 时重建整张场景。规则对象与模型展示分开：逻辑占格/碰撞代理决定通行，模型 Collider 不得偷偷改变规则。机关槽的可见模型与动画绑定改为明确组件/引用，避免现有按节点名寻找 Renderer 的方式误绑主题子物件。

主题配置至少包含稳定 themeId、版本、主题 Prefab、棋子/墙/门/传送展示、灯光/环境声、事件表现配置、UI 色板/故事引用、骰台绑定。LAN 房主选择 themeId，房间快照同步并校验本地目录；客户端不各自凭 PlayerPrefs 选不同主题。主题不改变骰子物理映射、速度或规则状态。

## 制作流程与验收

1. **材质与尺度样板：**每个拟用族选 5–10 个关键模型，复制到项目自有适配目录，建立 URP 材质/Prefab 变体。保留原贴图、UV、子材质、透明/双面和 Specular 工作流；先核查顶点色用途。原第三方资产保持原样。
2. **先完成一个场所：**以前线要塞做样板，先铺玩法核心和四角，再做近景功能带、2–3 个中景地标与远景。全程用普通对局镜头审阅，不只看模型近景。
3. **全规则物件覆盖：**逐项检查固定墙、升降墙、被压制槽、阵营门、配对传送、棋子底座、道具、选中圈/危险红圈。切换主题后行动预览和规则引导仍一致。
4. **完成主题引用契约：**再复制流程制作另外两张首批棋盘。不要同时搭五张半成品。
5. **第二批环境：**森林先解决树冠遮挡；港口先解决水、帆船和码头轮廓，然后补低频环境演出。

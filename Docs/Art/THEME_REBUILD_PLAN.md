# 五主题场景重搭与环境变化计划

2026-10-15，供用户确认。当前阶段只检查和整理方案，尚未执行场景、代码、材质或规则修改。

**细化目标：以《炉石传说》式精致、可探索的棋盘为参照，用现有 low poly 资产制作完整的微缩场所。所有主题的转角、收口、拼接与基脚都属于硬性验收；优先完成标准棋盘的整齐度、四角布景、连续外围和情境互动，再扩展天气/战损变体。**

用户已确认“增加变数”指布景、天气、损坏程度和环境演出。现有 19×19 地图、规则、胜利条件、AI 与棋盘点按保持。美术主题与环境变化不引入新的可走格、障碍、伤害、视野限制或机关效果。

## 一、当前问题及依据

本轮通过 Windows MCP 只读检查当前 SampleScene / ThemeContainer，并对照五张已保存的 Game View 截图和制作脚本。当前五个实例仍各有 363 个 BoardSurface 子件、208 个 FixedWalls 子件、72 个 FactionGates 子件、40 个 PairedPortals 子件和 9 个升降绑定。数量本身不是缺陷，但代码和画面共同说明这些主题仍沿用同一套造型模板。

1. **连接不成立。**`DriftlineThemeAuthoring.cs` 的固定墙生成只判断一侧轴向的邻居，在 0/90 度中选方向；没有端头、L 转角、T 连接、十字或宽墙区域处理。直沙袋、半墙和箱体逐格缩小后摆放，造成拐角不断、接头留缝和连续墙变成孤立小件。
2. **核心造型重复。**四个主题共用同一种 KayKit 地砖模型；各主题的地面材质大面积统一替换。九个升降机构、四色门阵、传送台与外围长条边框也采用同一几何，仅换配色。地城与机库因此同样呈现“平板、格线、小墙、几根柱子”。
3. **场所没有连成整体。**建筑、帐篷、柱、树、码头等分散在大平面上，缺少连续地基、道路、厅堂、舱壁、岸线等连接关系。港口的部分设施已补地基，但整体仍缺少完整港湾构图。
4. **镜头里的主题信息不足。**有些地标落在 HUD 遮挡区或远景边缘；默认俯角下，低墙细节和人物差异不足以承担主题识别。前中后景的体量与疏密缺少变化。
5. **重复过于整齐。**四角同款旗桶、等距树列、重复箱墙和均匀铺地，没有形成各主题自己的使用痕迹和空间节奏。
6. **外围互动没有真正接入。**现有 Adapter 移除源 Collider / Animator；旧 DraftlineToyProp 只有整体缩放与旋转，输入位于 BoardInteractionController 的回合控制限制之后。新主题需要自己的热点、可动部件和反馈，不能把普通装饰的存在当作互动完成。

上一轮的代码/构建测试证明了功能与资源绑定，不代表这些美术问题已通过验收。本轮以场所设计和实际画面为主要判断依据。

## 二、先补连接模块，再做场所构图

### 2.1 模块连接

从现有规则占格生成墙体连接参考，检查北/东/南/西四邻，覆盖孤立块、单端、直线、L 转角、T 连接、十字及其旋转。对连续多格厚墙处理外轮廓、内角和顶部填充，不把整个厚墙区域塞成空心墙线。

- 沙袋：使用单个 Sandbag 和直段组成同一占格内的 L/T 角，统一接缝和端头；缺少合适模块时制作项目自有组合 Prefab。
- 石墙：优先审查 KayKit 的 wall_corner_small / wall_endcap / wall_Tsplit / wall_crossing，以及 Polyworks Dungeon 的 inner/outer corner、连续墙和柱基。
- 科幻墙：优先审查 Polyperfect Scifi_Wall_Corner / Corridor / Edge 系列和 Polyworks SciFi Corner / Bulkhead 系列，选定一个主资产族，统一截面与接头。
- 林地：石垣、根系与断柱形成完整阻挡轮廓，根须与苔藓作为附着层。
- 港口：石护岸和木栅负责连续结构，货物成组摆放；拐角安排转角码头、系缆桩或完整箱堆。

连接规则只帮助制作和校验，完成结果仍保存为可编辑 Prefab。升降块与固定墙的接口单独处理：升起时衔接，落下时槽口与通道清楚。变体中的破损只改变顶部、表面与碎片，阻挡格始终有明确占格轮廓；不能做出视觉上可穿过、规则却不通的缺口。

### 2.2 每张场景独立出构图

每个主题先提交一张俯视摆位图和一张默认游戏镜头灰盒图，标出：玩法区、主体地标、功能分区、前景边界、外围通路，以及主菜单/HUD 的遮挡范围。

建筑地基、地面接缝、楼梯、道路、管线、岸线要把主体棋盘接进场所。外围轮廓、体量分布、负空间和地标位置逐张设计。批量工具用于基础连接和对齐，功能区与地标按实际镜头逐张布置。

高建筑、完整拱顶、树冠和桅杆集中在后方或侧后方；前景采用低护栏、残阶、地形断面、岸沿等。外围可有高差，玩法地面仍处于原来的高度和坐标。前景不新增可点击的“假入口”。

### 2.3 棋盘整齐与连接的统一标准

对五个主题及其环境状态使用同一份接缝清单。直墙、内外角、端头、厚墙、地砖边角、柱脚、屋角、护栏、栈桥和管线都检查，不能只修要塞。

- **玩法核心先规整：**统一格距、可走面标高、格线、地砖接缝、墙脚与棋子落脚高度。固定墙沿规则轮廓连续，降低装饰斜缝、碎纹和重复小凸起的干扰。
- **接口由几何决定：**为模块设置明确的接口与轴心，直段长度、截面和转角半径一致；基于相邻占格组合匹配模块，模型的包围盒居中缩放只用于资源初查，不作为最终拼接方式。
- **厚墙有内外两层关系：**外侧、内侧和顶部连续填充；转角不用两个直段互相穿插遮缝。连续掩体上的柱、帽石、铆钉或沙袋层数有规律地延续。
- **边界完整收口：**棋盘边框有转角、端盖、侧壁和底座，四条长条不能只在角上相碰。平台边缘向地形/建筑过渡，避免“棋盘放在一块巨大平面上”的观感。
- **有意破损仍可读：**顶部缺口、表面剥落、掉落小件有明确原因；地面保留阻挡轮廓。可走格不被装饰占据，破损不伪装成规则通道。
- **出图检查：**每主题提供俯视连接图和近景接头图，并检查升降机构的升起/落下两种状态；每次替换模块或制作环境状态后重新检查。

### 2.4 外围建设为连续的微缩舞台

构成为 **四个角部微场景 + 四边连续环境 + 完整地形/建筑底座**。四角各有主物件、配件、地面与互动，四边通过道路、墙体、树根、台阶、栈桥或管线将它们接在一起。

外围增加到足以形成完整场所的密度，模型按大/中/小三层组合：大件建立建筑/地形轮廓，中件形成设施与功能区，小件补充绳索、工具、木柴、弹药、苔藓、碎石等使用痕迹。每组小件围绕具体用途聚集，并保留道路、入口和必要空隙。

中央玩法区保持整洁、低对比；外围有更丰富的体量、材质和局部光照。low poly 的面数与造型特点通过比例统一、边缘处理、接触阴影、局部灯光和细节组合体现精度。外围层次不依赖全屏强雾、过度泛光或满屏粒子。

制作时使用带正式 HUD / 主菜单遮挡的镜头草图，标出四角可见、可点击的区域。根据实际屏幕空间安排微场景，必要时调整侧栏宽度与留白，保留现有功能和棋盘点按。主地标与交互物件不能藏在大面板后，也不能遮住出生格。

## 三、各主题的重搭设计

### 前线要塞：防线包围的演习场

主形状为粗厚防线和开阔作战庭院，材料为混凝土、帆布、沙袋、军绿色钢材。

- **核心：**将连续沙袋/混凝土掩体接成完整防线，转角加 L 形堆袋、角柱和收口。地面改为大块混凝土铺装与低对比作业线，避免满地装饰性斜砖纹。
- **外围：**后侧指挥所与营房组成同一院落，门、道路与车辆方向相通；左侧为补给卸货区，帐篷、货堆和卡车有前后关系；右侧为地堡和维修/待命车辆；前侧为低战壕、排水沟和断续沙袋。
- **机关：**装甲闸板/液压槽；出生区为部署垫与岗哨标识；传送为成对通讯信标，保留配对图形。
- **第一种状态：晴昼驻防。**补给整齐、旗帜轻动、少量扬尘、设施运行。
- **第二种状态：战损暮色。**同一防线的表面破损、停靠车辆替换、外围弹坑与少量烟柱、暖色工作灯。核心地面与棋子保持足够亮度。

### 符文地城：建在封印厅里的机关庭院

主形状为厚石墙、柱廊、拱券和向暗处延伸的厅堂；用石材冷色与局部火光制造层次。

- **核心：**连接的矮石墙、柱基与转角墩承担阻挡。主要石板、边缘装饰带和中心封印纹形成材质分区；格线服从规则网格，不让裂纹和花纹抢先被读成路线。
- **外围：**后方完整主拱与祭坛形成视觉焦点；两侧柱廊接回主厅，外廊/壁龛在画面边缘暗下去；前方残阶和断墙揭示大厅的剖面。各处墙脚、柱脚和石阶落在连续地基上。
- **机关：**升降石封印、嵌地符文门槛、刻纹传送阵；升降块与石地的构造一致。
- **第一种状态：封印苏醒。**维护较完整、暖火稳定、符文低频呼吸、外围微尘。
- **第二种状态：遗迹破败。**外围断柱/碎石、局部潮湿、少量冷雾与火焰扰动，所有阻挡格仍保持完整可读轮廓。

### 星舰机库：舱体内部的货运与训练甲板

主形状为成组舱壁、结构肋、技术面板、管线和不对称作业区，材料为冷灰金属、深色舱壁与琥珀警示件。

- **核心：**将目前满铺的小货箱改为连续低舱壁、机械隔断和防撞栏。地面采用大面板、嵌地轨道、检修盖与分区标线，接缝与玩法格一致。
- **外围：**后侧为机库门/泊机位与少量外舷信息；左侧维修终端、供电装置和通往核心的管线组成检修区；右侧为货运与输送区；前侧以低护栏、甲板边缘和设备沟收束。结构肋接到墙脚和甲板，不悬空摆放孤立门框。
- **机关：**带活塞/滑轨的机械挡板、权限部署舱、相位传输盘；动作反馈表现为机械状态与供电响应。
- **第一种状态：正常运作。**引导灯稳定、外围输送设施低频运转、终端工作。
- **第二种状态：维护检修。**外围打开的检修盖、机器人/工具车候选布景、局部检修灯和短促蒸汽。完整资产与兼容性在制作时核实；检修设施不进入可走区。

地城与机库并排审阅：隐藏主题名称、去掉主要色彩后，仍应能凭石厅/工业舱室的轮廓、连接方式、地面和机关造型区分。

### 暮林祭坛：森林正在收回的古代广场

主形状为不对称林缘、连续土坡/岩层、残留建筑和由外向内侵入的根系。

- **核心：**石垣按原阻挡布局连接，统一底座弱化为石材基础；根系、苔痕附着在墙面与外围，入口周边留出干净的脚印/踏石过渡。
- **外围：**后方祭坛和残拱形成遗址主体；左右采用树群、灌丛与高低岩层，打散当前等距树列；前方为低蕨类、土坡断面与入口石阶。苔草铺片融进土壤，去掉像单独样板一样的方形贴片边缘。
- **机关：**石根封印、树根包裹的部署台与符石传送阵。
- **第一种状态：林间斜阳。**局部树影、少量落叶/飞虫、安静的遗址。
- **第二种状态：雨后薄雾。**外围湿润石材、局部浅积水、低处薄雾与滴水。雾和树冠不遮挡棋子、终点与四角。

### 潮汐港口：沿岸展开的集散码头

主形状为石码头、木栈桥、岸线、水面和沿装卸方向摆放的货物；外围采用明显的长短边变化。

- **核心：**保留石质集散场，连续石护岸/木挡栏负责主要墙体；货箱以有承重关系的成组箱堆出现，减少每格一个相同箱子的重复。
- **外围：**后侧泊船真正靠接长栈桥与登船方向；左侧吊机、装卸区、货堆串联；右侧仓库门朝向货场，码头地基接回主场地；前侧为低岸沿、系缆桩和局部水面。建筑、楼梯、栈桥与地基接缝逐项检查。
- **机关：**带轨道的升降货运闸、泊位部署标识和航标传送设备。
- **第一种状态：晴日装卸。**轻浪、缆绳与旗帜微动、外围货运活动。
- **第二种状态：雾港黄昏。**灯笼/航标、低密度远处海雾、湿地与不同停靠船货。潮位变化只在玩法区外，不淹没或开放任何格子。

### 3.2 互动的完成标准

每张标准场景首轮安排四个直接互动，每个角至少一个。标准场景成熟后增加一个小连锁彩蛋，例如按顺序触发三个外围设备后出现短暂响应；彩蛋没有对局收益，也不新增规则提示。

1. **可发现：**可点物件有轻微待机动作、悬停轮廓或局部响应。热点大小按游戏镜头检查，玩家无需精准点中小零件。
2. **有用途感：**点击阀门、宝箱、机械臂和炮台分别产生符合物件用途的动作，不统一让整个模型旋转或弹跳。反馈包含运动，必要时搭配短声效和局部粒子。
3. **有后续状态：**至少两个直接互动支持重复点按的开/关、准备/执行或短循环变化；动作有结束与复位，不能靠堆叠补间无限漂移。
4. **等待时能玩：**等待对手、电脑决策或骰子结算时，外围互动仍可使用。菜单预览也能尝试可见的互动；设置/规则引导等覆盖层继续阻挡穿透点击。
5. **不干扰棋盘：**先处理 UI、规则目标与棋子/骰子，再处理外围热点。外围点击不会取消已选棋子、消耗道具、提交命令或改变镜头；特效、抛物轨迹和活动范围留在场外。
6. **联机职责明确：**主题状态/环境种子由房主同步；本机点按的玩具反馈先作为本地表现，不进入 MatchState、规则 RNG 或权威指令队列。无需等待网络确认即可响应。
7. **可以维护：**热点、可动件轴心、动作、声效、冷却、复位位置在 Prefab/Inspector 里可编辑。只为声明的互动补独立查询热点，不给所有装饰模型恢复物理碰撞。换主题、退菜单和停止 Play 时清理旧动作。

输入实现需要从目前受回合控制权限制的旧玩具点击分支中分离，统一点击优先级与事件消费。可动部件从静态合批中排除，静止底座与外围建筑继续合批。

参考 [暴雪官方荆棘谷棋盘介绍](https://hearthstone.blizzard.com/en-us/blog/9773962/) 的完整场所、轻待机动画与可发现互动，以及 [炉石音效团队访谈](https://hearthstone.blizzard.com/en-us/news/23964694) 对角部互动和隐藏触发序列的说明。上述角部布景和动作是本项目的设计提案。

## 四、环境变化怎样制作

保留 **五套主题、每套两种状态** 的目标。制作优先级调整为：先把标准棋盘的连接、外围构图与四角互动做完整，再扩展第二状态；天气和战损不能承担弥补基础构图的职责。暂不做任意组合天气、时段和损坏程度的组合爆炸。

1. **明确模板：**每种状态预先设计地标、小件、损坏和灯光配置。种子只控制经过约束的细节，例如旗帜相位、尘雾间隔、预选货堆位置；连接墙与主要构图始终确定。
2. **环境动态：**水波、旗帜、烟尘、微光、外围设备动作形成不同节奏。活动放在外围和功能设施，不在棋盘中心持续抢注意力。环境红光、闪光和符号不能被误读为阵营/危险/路径提示。
3. **损坏一致：**损坏围绕明确事件出现，例如要塞炮击侧、地城坍塌廊道、机库维修侧。不能把随机裂纹平均撒到所有地方；静态损坏也不能破坏规则轮廓。
4. **可复现选择：**主菜单主题下提供简洁的“场景状态：标准 / 第二状态 / 随机”选项，默认选择标准。玩家仍可使用已有简化效果设置减少天气和环境演出。最终名称随主题改变，例如晴昼驻防 / 战损暮色。
5. **联机一致：**房主确定主题状态及环境种子，进入房间/对局后保持。环境不读取或消耗规则 RNG，不改变 AI 或命令；客户端跟随布景状态，低配显示可以减少粒子。
6. **编辑与合批：**共享基础、状态差异与动态环境分层保存。当前静态合批层需要拆出可变件；入场先确定静止布景再合批，持续动画和粒子保持独立。所有模板、引用与摆位在 Prefab/配置中可修改。

优先使用已在项目中的模型。烟尘、雾、雨、水面等只把现有资源当候选，制作时逐项验证 URP、尺度和性能；不足的连接件以项目自有组合模块补齐，不为数量随意混入风格不同的资源包。

## 六、验收标准

- **结构：**直段、内外角、端头和转接处连续；无悬空柱脚、孤立门框、穿帮地基；厚墙占格与实际规则一致。
- **整齐：**五主题共用准确网格、标高和模块接口；近看墙帽、地砖、侧壁和底座有收口，模型没有因自动居中缩小而断开。
- **丰富：**四角都有完整微场景，四边有连续环境连接，大中小物件形成主次；核心清楚，外围能看到用途与使用痕迹。
- **互动：**每主题四处直接互动有明确的悬停/点击反馈、动作/声音/局部特效及结束复位；等待对手可用，棋盘命令与预览不受影响；用实际操作短录屏验收。
- **主题：**五张的地面组织、边界轮廓、建筑关系、门阵、传送、升降机构和光照分别设计。地城与机库的区别不依赖一冷一暖的色调。
- **构图：**默认视角下有可识别的主体地标和功能区，能看到连接关系；HUD 遮挡后仍成立；前景不挡四角与路线。
- **变化：**同主题两种状态在布景、使用痕迹和环境活动上有明显差异，规则与可走区域完全一致；随机结果能复现且不破坏接头和构图。
- **可读性：**1920×1080、1366×768、1280×720 及纯俯视能读清格子、阵营、传送配对、危险圈与路径；天气不遮挡输入目标。
- **编辑：**场景与状态仍能在 Prefab/Inspector 修改；重新 Play 不覆盖摆位；静态与动态层职责清楚。
- **功能/性能：**按主题验证选子、正常移动、急停、升降墙/占槽和主题状态切换；LAN 状态一致。分别采集独立程序的帧时间、绘制与内存，同口径比较首版。新增灯光/粒子与变化不能只靠显卡余量掩盖开销。
